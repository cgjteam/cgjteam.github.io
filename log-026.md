# Log 026 - The Suppes Interface: From Primitive Operations to Affine Geometry

**Date:** 2026-07-27  
**Project:** CGJteam Lab  
**Status:** Suppes Interface Reconstruction

---

## 1. Overview

`SuppesInterface.lean` is the first major derived layer above the active
Suppes axioms.

It imports

```lean
SuppesAxioms
```

and builds the geometric structures required by the later Midsegment and
Finlay developments.

The file introduces, among other notions,

```text
PrimTriangle
PrimParallelogram
SuppesParallel
```

and proves a substantial collection of midpoint, collinearity,
parallelogram, and parallelism results.

However, the reconstruction reveals an important qualification.

The file contains the comment

```text
This file contains only derived results.
```

but this is not literally true in the current implementation.

Two explicit assumptions remain:

```lean
suppes_parallel_transitivity
collinear_doubling_common_center
```

Thus the current interface is mostly derived, but not yet completely reduced
to `SuppesAxioms`.

---

## 2. Primitive Triangle

The first high-level geometric definition is

```lean
PrimTriangle A B C := not Col A B C.
```

Thus a primitive triangle is defined entirely through the primitive
collinearity relation of `SuppesGeometry`.

Schematically:

```text
Col
 |
 v
PrimTriangle
```

No line objects, angle objects, or metric predicates are introduced.

The triangle notion is therefore a direct noncollinearity condition in the
point language.

---

## 3. Primitive Parallelogram

The interface defines

```lean
PrimParallelogram A B C D
```

by combining two conditions:

```text
PrimTriangle A B C
```

and

$$
\operatorname{Mid}(A,C)=\operatorname{Mid}(B,D).
$$

Thus the primitive parallelogram is characterized by:

```text
nondegeneracy
      +
equality of diagonal midpoints
      |
      v
PrimParallelogram
```

This is fundamentally different from the Hilbert interface, where a
parallelogram is defined through two pairs of opposite parallel sides.

The Suppes route therefore starts from a midpoint-based description and must
later recover the familiar parallel-side description as a theorem.

---

## 4. Midpoint Algebra

A substantial first part of the file develops consequences of the midpoint
axioms.

Examples include:

```lean
midpoint_left_distrib
midpoint_fixed
doubling_reduction
```

The theorem

```lean
midpoint_left_distrib
```

has the affine identity

$$
\operatorname{Mid}\bigl(A,\operatorname{Mid}(B,C)\bigr)
=
\operatorname{Mid}\bigl(\operatorname{Mid}(A,B),\operatorname{Mid}(A,C)\bigr).
$$

This type of identity is characteristic of the Suppes route.

Rather than proving geometric facts through incidence and congruence
constructions, the theory manipulates midpoint and doubling operations
algebraically.

---

## 5. Suppes Theorem 11

The file reconstructs the midpoint configuration corresponding to Suppes'
Theorem 11.

The theorem

```lean
MidpointParallelogram
```

first produces the parallelogram

```text
P(Mid A B, Mid B C, Mid A C, A),
```

and after cyclic rotation the theorem

```lean
theorem11
```

gives

```text
P(A, Mid A B, Mid B C, Mid A C).
```

Schematically:

```text
triangle ABC
    |
    v
three midpoint constructions
    |
    v
primitive parallelogram
```

This is the Suppes analogue of the classical midsegment configuration.

The result does not yet mention a primitive parallel relation because
parallelism is introduced later as a derived notion.

---

## 6. Collinearity Transformations

The interface derives several basic transformations of `Col`.

Among them are:

```lean
collinear_swap
collinear_rotate
```

as well as local auxiliary swap lemmas used internally.

These results are derived from the Suppes collinearity axioms `L2` and `L3`.

Thus elementary reordering of collinear points is not taken as an additional
interface axiom.

Schematically:

```text
L2 / L3
   |
   v
collinear permutation laws
```

This parallels a pattern already seen on the Hilbert route: many operations
that feel primitive in paper geometry are proved once and then exposed as
reusable interface theorems.

---

## 7. Cyclic Parallelogram Structure

The file proves the cyclic behavior of primitive parallelograms.

The main theorem is

```lean
parallelogram_rotate3
```

which transforms

```text
P(A,B,C,D)
```

into

```text
P(D,A,B,C).
```

Its proof requires both:

- a midpoint identity,
- a nontrivial reconstruction of the triangle condition after rotation.

This is more than a notational symmetry.

Because `PrimParallelogram` includes a triangle hypothesis, rotating the
vertices requires proving that the new first three vertices remain
noncollinear.

This result becomes essential for later constructions involving
`SuppesParallel`.

---

## 8. Constructing a Primitive Parallelogram

The theorem

```lean
parallelogram_construct
```

constructs a canonical fourth vertex from a primitive triangle.

Schematically:

```text
PrimTriangle A B C
        |
        v
Dbl A (Mid B C)
        |
        v
PrimParallelogram C A B (Dbl A (Mid B C)).
```

This is a characteristic Suppes construction.

Existence is not expressed through an existential theorem. The fourth vertex
is explicitly given by midpoint and doubling operations.

This theorem later supports the recognition of a parallelogram from
parallel-side data.

---

## 9. Defining Suppes Parallelism

The interface introduces

```lean
SuppesParallel A B C D.
```

This is a derived relation.

Its definition combines four ingredients:

1. `PrimTriangle A B C`,
2. `C != D`,
3. a primitive parallelogram involving a constructed point
   `Dbl A (Mid B D)`,
4. a collinearity condition involving the same constructed point.

Schematically:

```text
triangle condition
       +
nondegeneracy
       +
constructed primitive parallelogram
       +
collinearity
       |
       v
SuppesParallel
```

Thus parallelism is not primitive and is not merely midpoint equality.

It packages a substantial affine construction.

This explains why familiar operations such as symmetry or reversal of a
parallel segment require real theorems.

---

## 10. A Parallelogram Produces Parallelism

The theorem

```lean
parallelogram_parallel_second
```

extracts a Suppes parallel relation from a primitive parallelogram.

This begins the connection between the midpoint-based parallelogram theory and
the more familiar language of parallel segments.

The proof uses:

```text
parallelogram rotation
construction of a new parallelogram
midpoint identities
collinearity
```

and therefore already illustrates the complexity hidden inside the compact
relation `SuppesParallel`.

---

## 11. Local Parallelogram Transitivity

The file also proves

```lean
parallelogram_transitive
```

corresponding to Suppes Theorem 12.

The theorem combines two primitive parallelograms and triangle conditions to
obtain a third primitive parallelogram.

Its proof is essentially midpoint algebra:

```text
two midpoint equalities
        |
        v
bicommutativity and cancellation
        |
        v
new midpoint equality
        |
        v
new PrimParallelogram
```

This result is genuinely derived from the formalized Suppes theory.

It should be distinguished from the later transitivity theorem for
`SuppesParallel`, which is not yet derived in the current file.

---

## 12. Reversal of a Parallel Segment

The theorem

```lean
parallel_reverse_second
```

proves

```text
AB || CD
   |
   v
AB || DC.
```

Its central affine ingredient is

```lean
collinear_double_mid_swap.
```

The latter transforms a collinearity relation of the form

```text
Col C (Dbl A (Mid B D)) D
```

into

```text
Col D (Dbl A (Mid B C)) C.
```

The proof uses midpoint distribution, bicommutativity, cancellation, and
collinearity transport.

This is an important example of a higher-level geometric symmetry being
reduced to explicit midpoint algebra.

---

## 13. First Remaining Assumption: Parallel Transitivity

The file contains the explicit axiom

```lean
axiom suppes_parallel_transitivity ...
```

with mathematical content corresponding to Suppes Theorem 16(iii):

```text
ab || pq
ab || rs
T(p,q,r)
---------
pq || rs.
```

The public theorem

```lean
parallel_transitive
```

is currently only a wrapper around this assumption.

Thus the dependency is:

```text
explicit interface assumption
        |
        v
parallel_transitive
```

rather than

```text
SuppesAxioms
        |
        v
formal derivation
        |
        v
parallel_transitive.
```

This is one of the principal remaining reduction obligations in the Suppes
route.

---

## 14. Second Remaining Assumption: Central Reflection

The file also contains

```lean
axiom collinear_doubling_common_center ...
```

which states that applying the same doubling operation about a common center
to three collinear points preserves collinearity.

Schematically:

```text
Col C X D
        |
        v
Col (Dbl X M) (Dbl C M) (Dbl D M).
```

Mathematically, this is the affine invariance of collinearity under central
reflection.

The theorem

```lean
collinear_central_reflection
```

is then proved from this assumption together with midpoint identities.

Thus:

```text
collinear_doubling_common_center   [axiom]
                |
                v
collinear_central_reflection       [theorem]
```

The distinction is important because the higher-level theorem is derived,
but its key affine engine is not yet reduced to the primitive Suppes axioms.

---

## 15. Symmetry of SuppesParallel

Using the previously developed machinery, the file proves

```lean
parallel_symm
```

with conclusion

```text
AB || CD
   |
   v
CD || AB.
```

The proof is substantial.

It reconstructs:

- the required triangle condition,
- the new primitive parallelogram,
- the new collinearity relation.

The final collinearity step uses the central-reflection theorem and therefore
depends on the explicit assumption

```lean
collinear_doubling_common_center.
```

Consequently, `parallel_symm` is an active theorem, but its full dependency
chain still contains one unreduced interface axiom.

---

## 16. Reversal of the First Segment

The theorem

```lean
parallel_reverse_first
```

is obtained economically from previously established interface operations.

The chain is:

```text
AB || CD
   |
   v
CD || AB
   |
   v
CD || BA
   |
   v
BA || CD.
```

Thus reversal of the first segment is not proved by another low-level
expansion of `SuppesParallel`.

It is assembled from:

```text
parallel_symm
parallel_reverse_second.
```

This is a good example of the interface beginning to behave as an ordinary
theory of parallelism once the basic structural theorems are available.

## 17. What Is Derived and What Is Not

The current `SuppesInterface` contains several logically different kinds of
declarations.

### Definitions

```text
PrimTriangle
PrimParallelogram
SuppesParallel
```

### Results derived from SuppesAxioms

Examples include:

```text
midpoint_left_distrib
midpoint_fixed
doubling_reduction
midpoint_triangle
MidpointParallelogram
parallelogram_rotate3
theorem11
collinear_swap
collinear_rotate
triangle_rotate
parallelogram_construct
parallelogram_parallel_second
parallelogram_transitive
collinear_double_mid_swap
parallel_reverse_second
parallel_reverse_first
```

### Theorems depending on remaining interface assumptions

Examples include:

```text
collinear_central_reflection
parallel_symm
```

### Explicit assumptions

```text
suppes_parallel_transitivity
collinear_doubling_common_center
```

This classification is more accurate than the comment that the file contains
only derived results.

## 18. The Actual Interface Boundary

The current logical architecture can therefore be represented as:

```text
SuppesAxioms
     |
     v
midpoint / doubling / collinearity theory
     |
     +--> primitive triangle theory
     |
     +--> primitive parallelogram theory
     |
     +--> Suppes Theorem 11
     |
     +--> derived parts of SuppesParallel
     |
     +-------------------------------+
     |                               |
     v                               v
explicit assumptions          derived interface
     |                               |
     +--> parallel transitivity      |
     +--> central-reflection law     |
     |                               |
     +---------------+---------------+
                     |
                     v
              SuppesParallel API
```

This is the correct boundary for the current reconstruction.

The file is neither a pure foundational theory nor merely a thin packaging
layer.

It is an active theory-development layer containing both substantial
derivations and a small amount of remaining foundational debt.

## 19. Comparison with HilbertInterface

The contrast with the Hilbert route is now instructive.

`HilbertInterface` currently acts mainly as a packaging and reduction layer
over a much larger foundational development.

`SuppesInterface` carries more of the mathematical development itself.

Schematically:

```text
Hilbert route

HilbertAxioms
    |
large derived theory
    |
HilbertInterface
    |
mostly packaging
```

whereas

```text
Suppes route

SuppesAxioms
    |
SuppesInterface
    |
substantial derived affine theory
    +
remaining explicit assumptions
```

Thus the two files have similar architectural positions but not the same
logical role.

This distinction should be preserved rather than hidden behind a uniform
naming convention.

## 20. Consequence for the Midsegment Route

The next file,

```lean
MidsegmentParallelSuppes.lean,
```

does not start directly from the primitive Suppes axioms.

It starts from the richer theory exposed by `SuppesInterface`.

In particular, the Midsegment route can consume:

```text
PrimTriangle
PrimParallelogram
SuppesParallel
Theorem 11
parallel transformations
```

without reopening their midpoint-algebraic proofs.

However, any final statement about the axiomatic strength of the Suppes
Midsegment Theorem must include the remaining explicit assumptions on which
these interface results depend.

## 21. Conclusion

`SuppesInterface.lean` is the main theory-building layer of the current
Suppes route.

It converts the primitive language

```text
Mid
Dbl
Col
```

into a recognizable affine geometry containing

```text
triangle
parallelogram
parallelism
```

and proves much of the required structure formally.

The central progression is:

```text
Suppes primitive operations
        |
        v
midpoint and collinearity algebra
        |
        v
PrimTriangle / PrimParallelogram
        |
        v
SuppesParallel
        |
        v
parallelism interface
        |
        v
higher-level synthetic geometry
```

but the reduction is not yet complete.

Two explicit assumptions remain visible:

```text
suppes_parallel_transitivity
collinear_doubling_common_center.
```

Therefore the correct interpretation of the current interface is:

> a largely derived affine theory with a small number of explicit remaining
> theoretical assumptions.

The next reconstruction should inspect `MidsegmentParallelSuppes.lean` and
determine exactly which parts of this interface are required to recover the
Midsegment Theorem on the Suppes route.
