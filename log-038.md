# Log 036 --- Simplifying the Tarski Architecture

## Objective

This session began a systematic simplification of the Tarski route to
Finlay's proof.

The existing Tarski development had accumulated a substantial interface
layer during the reconstruction of the Midsegment Theorem and Finlay's
argument. Some declarations represented genuine dependencies of the
current proof, while others were remnants of earlier constructions or
intermediate approaches.

The objective was therefore to determine the actual dependency structure
of the working Tarski formalization and remove unnecessary components
without changing the proof itself.

## FinlayProofTarski as the reference point

The active `FinlayProofTarski` development was taken as the reference
point for the audit.

Instead of preserving declarations because they might be useful in a
more general Tarski library, the audit asked a narrower question:

> Which parts of the current Tarski infrastructure are actually required
> by Finlay's proof and its real dependencies?

This changed the direction of the refactoring.

The task was no longer to enlarge the Tarski interface, but to reduce it
to the mathematical infrastructure actually supporting the current
formal development.

## Dependency-driven reduction

Declarations in `TarskiInterface` were examined against the active proof
chain.

For each declaration, the audit distinguished between:

-   components directly used by `FinlayProofTarski`,
-   components used indirectly by its dependencies,
-   infrastructure required by the Midsegment development,
-   declarations left over from previous versions of the proof,
-   unused auxiliary results.

Unused components could then be removed or temporarily disabled and the
complete project rebuilt.

This provided a direct test of whether a declaration belonged to the
active logical structure of the proof.

## Separating proof architecture from library accumulation

The audit exposed an important distinction between two different
development strategies.

A general-purpose geometry library tends to accumulate useful results.

A proof-oriented formalization can instead use the dependency graph of a
concrete theorem to determine which results are currently justified as
part of its architecture.

For the Tarski route, the second strategy proved more informative.

The resulting interface is not intended to represent all useful
consequences of Tarski geometry. It represents the portion of the theory
currently required to support the formal reconstruction under
investigation.

## Deferred results

The reduction also made the remaining deferred results more visible.

Once unused declarations were removed, the assumptions still present in
the active dependency chain could be examined individually.

This transformed the remaining axioms from an undifferentiated
collection of temporary interface results into explicit targets for
further mathematical reconstruction.

The next stage therefore became not further API expansion, but
theorem-by-theorem analysis of these remaining assumptions.

## Architectural consequence

The Tarski route now has a clearer dependency direction:

    Tarski primitives
          ↓
    Tarski axioms
          ↓
    derived Tarski geometry
          ↓
    required interface results
          ↓
    Midsegment theorem
          ↓
    Finlay proof

The purpose of the interface is no longer to collect potentially useful
geometric facts.

Its role is to expose precisely the derived geometry required by the
higher-level proof.

## Result

The Tarski development was reduced to a smaller and more transparent
active dependency structure.

The working Finlay proof remained unchanged at the mathematical level,
while unnecessary interface components could be removed.

More importantly, the reduction isolated the remaining deferred
assumptions as concrete mathematical problems.

This established the next phase of the project: reconstructing those
assumptions from the underlying Tarski theory wherever possible.
