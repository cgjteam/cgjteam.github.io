# Log-022

# The Axiomatic Structure of the Hilbert Route

**Date:** 2026-07-27
**Project:** CGJteam Lab
**Status:** Hilbert Axiom Layer Reconstruction

---

## 1. Overview

The reconstruction of the Hilbert route to Finlay's proof requires a
precise distinction between the primitive geometric language and the
axioms imposed on that language.

`HilbertCore.lean` provides primitive relations and representations of
derived geometric objects.

`HilbertAxioms.lean` introduces the actual axiomatic hierarchy.

The current file is substantially more developed than an incidence-only
foundation. It contains a hierarchy corresponding to the major groups
of Hilbert's axioms together with a large body of formally derived
neutral and Euclidean geometry.

Schematically, the structure is:

```text
HilbertIncidence
        |
        v
HilbertPlaneIncidence
        |
        v
HilbertOrder
        |
        v
HilbertCongruence
        |
        v
HilbertEuclideanPlane
        |
        v
HilbertArchimedeanPlane
```

The important question for the Finlay route is therefore not simply
whether the proof depends on `HilbertAxioms`.

The more precise question is:

```text
How far up this hierarchy does the proof actually need to go?
```

---

## 2. A Second Incidence Relation

The first architectural observation concerns incidence itself.

`HilbertCore` already contains a primitive field:

```lean
Geo.OnLine
```

However, `HilbertAxioms` introduces the class:

```lean
class HilbertIncidence where
  OnLine :
    Geo.Point -> Geo.Line -> Prop
```

The incidence relation used in the Hilbert axiomatic development is
therefore supplied by `HilbertIncidence`.

From this relation the file defines:

```lean
PrimCollinear
```

with the mathematical meaning:

```text
PrimCollinear A B C
    :=
there exists a line l such that
A lies on l,
B lies on l,
C lies on l.
```

Thus the immediate dependency is:

```text
HilbertIncidence.OnLine
        |
        v
PrimCollinear
```

This creates an architectural question that must be resolved at the
interface level.

The current development contains both:

```text
Geo.OnLine
```

and

```text
HilbertIncidence.OnLine.
```

The later reconstruction of `HilbertInterface` must determine exactly
where these two layers are connected, interpreted, or identified.

---

## 3. Auxiliary Definitions

Before the main Hilbert axiom classes are introduced, the file defines
several notions needed to formulate the geometry.

These include:

```lean
HilbertLinesMeet
HilbertLinesDisjoint
HilbertSameRay
HilbertSegmentMeetsLine
HilbertSameSideStep
HilbertSameSide
HilbertOppositeSide
```

These are definitions rather than new axioms.

They organize the primitive incidence and betweenness relations into
higher-level notions needed by the order axioms, Pasch's axiom, angle
construction, and parallelism arguments.

Schematically:

```text
HilbertIncidence.OnLine
        +
      Between
        |
        +--> HilbertLinesMeet
        |
        +--> HilbertLinesDisjoint
        |
        +--> HilbertSameRay
        |
        +--> HilbertSegmentMeetsLine
                    |
                    +--> HilbertSameSide
                    |
                    `--> HilbertOppositeSide
```

This is the first example of the general architecture of
`HilbertAxioms`: relatively small axiom classes are surrounded by a
larger derived geometric language.

---

## 4. Group I: Incidence

The first substantial axiomatic layer is represented by:

```lean
class HilbertPlaneIncidence
```

This extends the basic incidence structure with the plane incidence
axioms.

The class contains principles corresponding to:

```text
I.1  line_through
I.2  line_unique
I.3  two_points_on_line
I.3  three_noncollinear
```

Their mathematical content is approximately:

```text
two distinct points determine a line,

the line through two distinct points is unique,

there exists a line containing two distinct points,

there exist three noncollinear points.
```

This is the first point in the Hilbert route where genuine geometric
axioms appear.

The dependency structure becomes:

```text
HilbertIncidence
        |
        v
HilbertPlaneIncidence
        |
        v
plane incidence geometry
```

The distinction between this layer and `HilbertCore` is fundamental.

`HilbertCore` provides the vocabulary.

`HilbertPlaneIncidence` begins to state what that vocabulary must
satisfy.

---

## 5. Group II: Order

The next layer is:

```lean
class HilbertOrder
  extends HilbertPlaneIncidence
```

This introduces the axiomatic behavior of the primitive relation
`Between`.

The main fields correspond to:

```text
II.1  between_incidence
II.2  between_extension
II.3  between_unique
II.4  pasch
```

Thus the architecture separates the existence of a primitive
betweenness relation from the laws governing it.

Schematically:

```text
HilbertCore
        |
        | primitive relation
        v
     Between
        |
        | Hilbert axioms of order
        v
   HilbertOrder
```

The distinction is important.

`Between` is part of the language before any order geometry is assumed.
Its geometric meaning is imposed only at the `HilbertOrder` level.

Pasch's axiom also enters at this level and becomes one of the major
sources of derived plane geometry later in the file.

---

## 6. Group III: Congruence

The next major class is:

```lean
class HilbertCongruence
  extends HilbertOrder
```

This introduces the Hilbert congruence axioms.

The principal components include:

```text
III.1  segment_construction
III.2  segment_congruence_common
III.3  segment_additivity
III.4  angle_construction
       angle_congruence_reflexive
III.5  sas
```

This is particularly important for the route to the Midsegment Theorem.

The SAS principle is present here as a genuine Hilbert axiom:

```lean
sas
```

Above this level, however, several familiar triangle-congruence tools
are derived rather than assumed independently.

The file proves results including:

```lean
hilbert_sas_remaining_angles
hilbert_sas_third_side_and_angle
hilbert_asa_sides
hilbert_aas_sides
```

Thus the logical structure is:

```text
Hilbert SAS axiom
        |
        v
derived SAS consequences
        |
        +--> remaining equal angles
        |
        +--> third-side congruence
        |
        +--> ASA consequences
        |
        `--> AAS consequences
```

This distinction matters for the later analysis of
`MidsegmentParallel`.

A high-level theorem may invoke an interface result called `SAS`, but
the actual foundational dependency can ultimately terminate in the
single Hilbert congruence axiom.

---

## 7. Derived Neutral Geometry

After the introduction of `HilbertCongruence`, a substantial part of
`HilbertAxioms.lean` consists of formally derived geometry.

This layer no longer adds new primitive assumptions at every step.
Instead it develops consequences of Groups I-III.

Representative results include:

```lean
hilbert_primCollinear_trans
hilbert_point_off_line
hilbert_between_on_line
hilbert_between_exists
hilbert_pasch_forced
hilbert_between_trichotomy
```

together with stronger forms of Pasch:

```lean
hilbert_inner_pasch_strong
hilbert_outer_pasch_strong
```

and extensive theories of rays and sides of lines:

```text
HilbertSameRay
HilbertSameSide
HilbertOppositeSide
```

The file also derives standard congruence properties such as:

```lean
hilbert_congruent_reflexive
hilbert_congruent_symmetry
hilbert_congruent_transitivity
```

as well as increasingly substantial synthetic results.

The resulting layer can be viewed as:

```text
Groups I-III
     |
     v
Neutral Geometry
     |
     +--> incidence consequences
     +--> order consequences
     +--> Pasch machinery
     +--> ray geometry
     +--> side-of-line geometry
     +--> triangle congruence
     `--> angle geometry
```

This is a significant architectural boundary.

Many statements used by later synthetic proofs are no longer axioms.
They are already theorems of the Hilbert foundation.

---

## 8. Alternate Angles Imply Parallelism

One of the most important derived results for the Finlay route is:

```lean
hilbert_parallel_of_alternate_angles
```

Its mathematical content is the familiar implication:

```text
equal alternate angles
        |
        v
parallel lines
```

Crucially, this theorem occurs in the neutral part of the development,
before the Euclidean parallel axiom is introduced.

Therefore the implication

```text
equal alternate angles -> parallel
```

does not require Hilbert Group IV.

This observation is directly relevant to the conceptual structure of
`MidsegmentParallel`, which contains the transition:

```text
SAS
 |
 v
Equal Angles
 |
 v
Parallelism
```

The foundational path may therefore be:

```text
Hilbert Groups I-III
        |
        v
SAS
        |
        v
equal angles
        |
        v
hilbert_parallel_of_alternate_angles
        |
        v
parallel lines
```

without invoking the Euclidean parallel axiom.

This is one of the first indications that the Hilbert route to Finlay's
proof may require less axiomatic strength than the complete
`HilbertAxioms` hierarchy provides.

## 9. Midpoint Existence

Another important derived result is:

```lean
hilbert_midpoint_exists
```

This theorem is established before the Euclidean parallel axiom.

Thus midpoint existence belongs to the neutral part of the current
Hilbert development.

This gives another useful distinction:

```text
midpoint
```

is not introduced as an independent primitive construction required
specifically for Finlay's proof.

Instead, the relevant existence result is formally derived from the
earlier Hilbert geometry.

The dependency has the form:

```text
Hilbert Groups I-III
        |
        v
neutral geometric development
        |
        v
hilbert_midpoint_exists
```

This will later have to be compared with the public `IsMidpoint`
interface used by `MidsegmentParallel` and `FinlayProof`.

## 10. Group IV: Euclidean Parallel Axiom

Only after the neutral development does the file introduce:

```lean
class HilbertEuclideanPlane
  extends HilbertCongruence
```

Its characteristic additional assumption is:

```lean
parallel_unique
```

This expresses the Hilbert parallel axiom in uniqueness form.

Mathematically, through a point outside a given line there is at most
one line disjoint from the given line.

The hierarchy therefore becomes:

```text
HilbertCongruence
        |
        | Groups I-III
        v
Neutral Geometry
        |
        v
HilbertEuclideanPlane
        |
        | Group IV
        v
Euclidean Geometry
```

The file then proves the converse direction of the alternate-angle
criterion:

```lean
hilbert_alternate_angles_of_parallel
```

Thus the two implications have different logical strengths.

The neutral direction is:

```text
equal alternate angles
        |
        v
parallel
```

while the Euclidean direction is:

```text
parallel
        |
        v
equal alternate angles
```

This separation is mathematically significant.

It shows exactly where the Euclidean parallel axiom enters the current
formal theory.

The development also introduces the auxiliary construction:

HilbertSegmentChain

## 12. Axioms Versus Derived Geometry

The reconstruction reveals that `HilbertAxioms.lean` should not be
treated as a flat collection of assumptions.

It contains at least three logically different kinds of declarations.

First, there are definitions used to express geometric configurations:

```text
HilbertLinesMeet
HilbertSameRay
HilbertSameSide
HilbertOppositeSide
...
```

Second, there are genuine axiomatic classes:

```text
HilbertPlaneIncidence
HilbertOrder
HilbertCongruence
HilbertEuclideanPlane
HilbertArchimedeanPlane
```

Third, there is a large derived theory:

```text
Pasch consequences
ray and side geometry
congruence equivalence properties
triangle congruence results
angle theorems
parallel criteria
midpoint existence
...
```

Consequently, a theorem imported from `HilbertAxioms` is not necessarily
an additional assumption.

Its true dependency must be traced to the lowest axiom class required
by its proof.

## 14. The Main Dependency Question

The original rough dependency:

```text
MidsegmentParallel
        |
        v
HilbertAxioms
```

is therefore too coarse.

The correct question is:

```text
What is the weakest Hilbert axiom class required by
each component of MidsegmentParallel?
```

In particular, we must determine whether the complete proof requires:

```text
HilbertEuclideanPlane
```

or whether:

```text
HilbertCongruence
```

together with the neutral geometry already derived from Groups I-III is
sufficient.

The answer cannot be obtained from the mathematical statement alone.

It depends on the actual declarations exposed by `HilbertInterface` and
the instance requirements attached to them.

---

## 15. Architectural Boundary to Be Inspected

The next file in the reconstruction is:

```text
HilbertInterface.lean
```

This file is now especially important.

It must explain how the large foundational theory developed in
`HilbertAxioms` is presented to the reusable synthetic geometry layer.

The reconstruction must determine:

1. how `PrimCollinear` is connected to the public collinearity relation,
2. how the incidence relation in `HilbertIncidence` relates to the
   primitive `Geo.OnLine` field,
3. which Hilbert classes are required by the public interface,
4. which interface results are proved from `HilbertAxioms`,
5. which interface results remain explicit assumptions,
6. whether the interface unnecessarily strengthens neutral results to
   `HilbertEuclideanPlane`,
7. which declarations are actually consumed by
   `MidsegmentParallel`.

The next dependency boundary is therefore:

```text
HilbertAxioms
        |
        | interpretation and packaging
        v
HilbertInterface
        |
        | reusable synthetic API
        v
MidsegmentParallel
```

Only after reconstructing this boundary will it be possible to state
the actual axiomatic strength of the Hilbert route to Finlay's proof.

---

## 16. Current Conclusion

The present Hilbert foundation is considerably richer than an
incidence-only architecture.

Its actual structure is hierarchical:

```text
primitive geometric language
        |
        v
incidence axioms
        |
        v
order axioms
        |
        v
congruence axioms
        |
        v
neutral geometry
        |
        v
Euclidean parallel axiom
        |
        v
Euclidean geometry
        |
        v
Archimedean extension
```

For the Finlay project, the most important discovery at this stage is
that the complete hierarchy should not be attributed automatically to
the proof.

Several constructions that might superficially look Euclidean are
already derived before Group IV.

In particular:

```text
SAS
midpoint existence
equal alternate angles -> parallel
```

belong to the development available at or below the
`HilbertCongruence` level.

The next stage of the reconstruction is therefore not to add or modify
axioms.

It is to inspect `HilbertInterface.lean` and determine exactly how much
of this hierarchy reaches the synthetic proof layer.
