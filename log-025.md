# Log 025 - The Axiomatic Structure of the Suppes Route

**Date:** 2026-07-27  
**Project:** CGJteam Lab  
**Status:** Suppes Axiom Layer Reconstruction

---

## 1. Overview

The reconstruction of the current Suppes route begins with an architectural
observation.

The repository contains a file

```lean
SuppesCore.lean
```

defining a structure `SuppesGeo` with primitive data of the form

```lean
Point
S
I
alpha
beta
gamma
```

but the active Suppes route to the Midsegment Theorem and Finlay's proof does
not currently descend through this structure.

Instead, the active foundational file is

```lean
SuppesAxioms.lean.
```

It introduces a separate class, `SuppesGeometry`, whose primitive geometric
language is based on midpoint, doubling, and collinearity.

Thus the first result of the reconstruction is the distinction

```text
SuppesCore.lean
    |
    `-- SuppesGeo
        Point, S, I, alpha, beta, gamma

currently separate from

SuppesAxioms.lean
    |
    `-- SuppesGeometry
        Mid, Dbl, Col
```

The relation between these two structures is not part of the active proof
route inspected here.

---

## 2. The Active Primitive Language

The active Suppes axiomatic development is organized around

```lean
class SuppesGeometry (Point : Type*) where
  operation_midpoint : Point -> Point -> Point
  operation_double   : Point -> Point -> Point
  Collinear          : Point -> Point -> Point -> Prop
```

The interface then uses the abbreviations

```text
Mid
Dbl
Col
```

for these operations and relation.

Schematically:

```text
Point
 |
 +--> Mid : Point x Point -> Point
 |
 +--> Dbl : Point x Point -> Point
 |
 `--> Col : Point x Point x Point -> Prop
```

This is already a major contrast with the Hilbert route.

The active Suppes foundation does not begin with primitive lines, incidence,
betweenness, segment congruence, or angle congruence.

Instead, midpoint and doubling are primitive operations in the language.

---

## 3. Constructive Operations

The use of operations rather than existential construction statements is
structurally important.

For two points \(a\) and \(b\),

$$
\operatorname{Mid}(a,b)
$$

denotes a point directly.

Likewise,

$$
\operatorname{Dbl}(a,b)
$$

denotes the point obtained through the doubling operation.

Thus constructions that would require existence theorems in another
foundation can appear here as terms of the language.

This gives the active Suppes route a characteristic form:

```text
primitive operations
        |
        v
identities between constructed points
        |
        v
derived affine configurations
```

The logical work is shifted from proving existence of the constructed point
to proving identities and collinearity relations involving the operations.

---

## 4. The Axiom Families

`SuppesAxioms.lean` organizes the basic theory through a collection of named
axioms associated with the midpoint, doubling, and collinearity language.

The active families include declarations labelled

```text
L2
L3

B1
B2
B3
B4

D1
D2
D3

BD
LB
LL
```

The labels should be read as names of the formal axioms used in the current
Suppes development.

For the present reconstruction, the important fact is their structural role:

```text
SuppesGeometry
      |
      v
L / B / D axioms and interaction laws
      |
      v
derived midpoint, doubling, and collinearity theory
```

A detailed mathematical catalogue of every axiom belongs more naturally to a
reference page than to this reconstruction log.

---

## 5. Collinearity

Unlike the Hilbert route, the active Suppes foundation does not reconstruct
collinearity from primitive incidence with a line.

`Col` is already part of `SuppesGeometry`.

The axioms then constrain its behavior and its interaction with the
constructive operations.

Thus the active dependency begins as

```text
SuppesGeometry.Collinear
          |
          v
collinearity axioms
          |
          v
derived collinearity lemmas
```

This is one of the clearest foundational differences between the Hilbert and
Suppes routes.

---

## 6. Midpoint and Doubling

The operations `Mid` and `Dbl` are not merely convenient definitions added
above the axioms.

They belong to the primitive structure of the active Suppes theory.

Their algebraic interaction is controlled by the axiom families in
`SuppesAxioms.lean`.

This allows later proofs to manipulate configurations through equations such
as midpoint identities and doubling identities.

The characteristic proof language is therefore closer to affine point
algebra:

```text
Mid / Dbl identities
        +
collinearity
        |
        v
geometric configuration
```

rather than to the incidence-order-congruence construction chain used by the
Hilbert route.

---

## 7. Ambient Algebraic Context

The file also declares an ambient algebraic context involving structures of
the form

```text
Ring R
Invertible 2
AddCommGroup V
Module R V
AddTorsor V Point
```

This context must be distinguished from the primitive fields of
`SuppesGeometry`.

The axiomatic language itself is expressed through points, `Mid`, `Dbl`, and
`Col`.

The presence of the ambient module and torsor assumptions in the file does not
by itself show that every Suppes axiom or every later theorem depends
essentially on them.

Determining which declarations genuinely require this algebraic context is a
separate dependency question for later reduction.

---

## 8. No Active Dependency on SuppesCore

The current reconstruction reveals an important architectural discontinuity.

The active chain begins with

```text
SuppesAxioms
      |
      v
SuppesInterface
```

while the structure declared in `SuppesCore.lean` is not imported into this
chain.

Therefore the current repository should not be represented as if it had the
dependency

```text
SuppesCore
    |
    v
SuppesAxioms.
```

That dependency does not currently exist in the inspected route.

Instead:

```text
                 SuppesCore
                     |
                  SuppesGeo
                     |
                 [separate]

SuppesAxioms
     |
 SuppesGeometry
     |
     v
SuppesInterface
```

Whether `SuppesGeo` is intended as a future lower-level reconstruction,
another formulation of Suppes' primitive language, or an experimental branch
is not determined by the active dependency graph alone.

The log therefore records the separation without assigning it a role that the
code does not yet establish.

---

## 9. Comparison with the Hilbert Foundation

The contrast with the Hilbert route is now explicit.

The reconstructed Hilbert route begins schematically with

```text
Point / Line / OnLine
Between
SegmentCongruent
UnorientedAngleCongruent
        |
        v
Hilbert axiom classes
```

whereas the active Suppes route begins with

```text
Point
Mid
Dbl
Col
        |
        v
Suppes axioms
```

Thus the two routes do not merely provide different proofs above a common
primitive geometry.

Their primitive vocabularies are different.

Schematically:

```text
Hilbert                         Suppes

incidence                       midpoint operation
order                           doubling operation
congruence                      collinearity
angles
    |                               |
    v                               v
Hilbert axioms                  Suppes axioms
```

The common synthetic vocabulary must therefore appear above these
foundational differences.

## 10. The Next Layer

The next active file is

```lean
SuppesInterface.lean.
```

It introduces familiar geometric structures and derived theory above the
primitive Suppes language.

Among the notions appearing there are:

```text
PrimTriangle
PrimParallelogram
SuppesParallel
```

together with midpoint, parallelogram, and parallelism results.

The active route is therefore:

```text
SuppesAxioms
     |
     v
SuppesInterface
     |
     v
MidsegmentParallelSuppes
     |
     v
FinlayProofSuppes
```

This is the dependency chain that must be reconstructed before the logical
status of the Suppes-based Finlay proof can be assessed.

---

## 11. Axiom Boundary and Interface Debt

Inspection of `SuppesInterface.lean` already shows that not every declaration
above `SuppesAxioms` is currently derived.

The interface contains explicit assumptions such as

```lean
suppes_parallel_transitivity
collinear_doubling_common_center
```

used to complete parts of the higher-level affine theory.

This fact is important for interpreting the active route.

Compilation of `FinlayProofSuppes` does not by itself mean that the theorem has
already been reduced completely to the axioms declared in
`SuppesAxioms.lean`.

The current structure is more accurately represented as

```text
SuppesAxioms
      |
      v
derived Suppes theory
      |
      +---- remaining explicit assumptions
      |
      v
SuppesInterface
      |
      v
higher-level proofs
```

The remaining assumptions are therefore visible foundational obligations,
not hidden implementation details.

---

## 12. Conclusion

The first stage of the current Suppes reconstruction identifies the actual
foundation used by the active proof route.

It is not presently

```text
SuppesCore -> SuppesAxioms.
```

Instead, the route begins directly with the independent structure

```text
SuppesGeometry
```

defined in `SuppesAxioms.lean`, with primitive operations and relation

```text
Mid
Dbl
Col.
```

The resulting foundational architecture is

```text
SuppesGeometry
      |
      v
Suppes axioms
      |
      v
derived midpoint / doubling / collinearity theory
      |
      v
SuppesInterface
```

while `SuppesCore.lean` remains outside this active dependency chain.

This distinction is essential before analysing the next layer.

The next reconstruction must determine exactly what `SuppesInterface` derives
from this foundation, what geometric vocabulary it introduces, and which
explicit assumptions still remain between the primitive Suppes theory and the
synthetic language used by Finlay.
