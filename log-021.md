# Log-021

# The Hilbert Route to Finlay's Proof

**Date:** 2026-07-27
**Project:** CGJteam Lab
**Status:** Hilbert Route Reconstruction

---

## 1. Overview

The goal of this log is to reconstruct the current Hilbert-based route
to Finlay's proof in the CGJteam Lab Lean library.

The reconstruction follows the actual current code rather than historical
versions of the library or a reconstruction from memory.

The main dependency path is:

```text
HilbertCore
    |
HilbertAxioms
    |
HilbertInterface
    |
MidsegmentParallel
    |
FinlayProof
```

The analysis proceeds mathematics first and Lean implementation second.

For each layer we distinguish between primitive objects and relations,
definitions, genuine Hilbert axioms, formally derived results, interface
assumptions, and the results actually used by the Midsegment Theorem and
Finlay's proof.

The first layer is `HilbertCore.lean`.

---

## 2. HilbertCore: The Primitive Language

`HilbertCore.lean` does not yet contain the Hilbert axioms.

Its role is to define the geometric language in which the axioms and
subsequent theorems will be expressed.

At this level the library contains:

```text
primitive geometric language
        +
representations of derived objects
        +
structural consequences of those representations
```

but not yet Hilbert geometry as an axiomatic theory.

---

## 3. Primitive Objects and Relations

The structure `Geo` contains two primitive types:

```lean
Point : Type u
Line  : Type u
```

Thus the foundation is a two-sorted point-line language.

The core also contains four primitive geometric relations:

```lean
OnLine
Between
SegmentCongruent
UnorientedAngleCongruent
```

Their intended mathematical meanings are:

```text
Point                     point
Line                      line
OnLine P l                P lies on l
Between A B C             B lies between A and C
SegmentCongruent          congruence of unoriented segments
UnorientedAngleCongruent  primitive angle-congruence relation
```

At this stage no Hilbert axiom specifies how these relations behave.

For example, merely having the relation `Between` does not imply any of
Hilbert's order axioms. Similarly, `OnLine` does not yet imply the
incidence axioms.

---

## 4. Rays, Collinearity, and Point-Defined Lines

A substantial part of the geometric language is already constructed
inside `HilbertCore`.

The relation `Between` is used to define the elementary directional
relation `SameDirectionStep`, which in turn participates in the
construction of rays:

```text
Between
   |
SameDirectionStep
   |
  ray
```

The core proves structural results including:

```lean
sameDirectionStep_symm
ray_eq_of_sameDirectionStep
```

These require no Hilbert axiom.

The core also introduces a betweenness-based three-point collinearity
predicate, `LineCollinear`. It is defined using point equalities together
with the possible orientations of the `Between` relation.

Separately, `PointLine A B` represents the extensional set of points
collinear with `A` and `B`.

Schematically:

```text
Between
   |
LineCollinear
   |
PointLine A B = { X | LineCollinear A B X }
```

The core proves:

```lean
pointLine_swap
```

expressing that the point-defined line `AB` is the same as `BA`.

This is a point-defined, betweenness-based notion of line. It should be
distinguished from the primitive type `Line` together with the primitive
incidence relation `OnLine`. The relation between these two descriptions
belongs to the later Hilbert incidence layer.

---

## 5. Parallelism

Parallelism is not a primitive relation of the Hilbert core.

It is defined from point-defined lines. Schematically:

```text
Between
   |
LineCollinear
   |
PointLine
   |
Parallel
```

The definition has the form:

```lean
def Parallel ... :=
  A != B &&
  C != D &&
  Disjoint (Geo.PointLine A B) (Geo.PointLine C D)
```

Thus two point-defined lines are parallel when both defining pairs are
nondegenerate and the corresponding extensional lines are disjoint.

This is an important architectural fact for the later dependency
analysis:

```text
Parallel is derived, not primitive.
```

The core already proves structural properties including:

```lean
parallel_symmetry
parallel_swap_first
parallel_swap_second
```

These results follow from the definition of parallelism and the
representation of point-defined lines.

---

## 6. Segments and Congruence

Segments are represented in the core so that endpoint reversal is built
into the segment object.

Schematically:

```text
Point
  |
Segment
  |
Congruent
```

The primitive relation `SegmentCongruent` acts on these segment objects.

Because endpoint reversal is absorbed by the representation, reversing
the endpoints does not produce a new segment:

```text
AB = BA
```

This is a property of the representation rather than a geometric theorem
requiring a Hilbert axiom.

The core consequently proves:

```lean
segment_swap
congruent_reverse_first
congruent_reverse_second
```

These are structural consequences of the chosen representation.

---

## 7. Angles and Angle Congruence

Angles are constructed from rays:

```text
Between
   |
  ray
   |
 Angle
```

An angle is represented so that exchanging its two boundary rays does
not change the represented unoriented angle.

Consequently, reversing the two sides is a representation-level symmetry.

This gives structural results including:

```lean
angle_swap
angle_congruent_reverse_first
angle_congruent_reverse_second
```

Again, these are consequences of representation rather than Hilbert
axioms.

There is an additional important construction.

The public relation

```lean
AngleCongruent
```

is not simply the primitive relation

```lean
UnorientedAngleCongruent
```

Instead it is constructed using:

```lean
Relation.EqvGen Geo.UnorientedAngleCongruent
```

The dependency is therefore:

```text
UnorientedAngleCongruent
          |
        EqvGen
          |
   AngleCongruent
```

As a result, the core can already prove:

```lean
angle_congruent_reflexive
angle_congruent_symmetry
angle_congruent_transitivity
```

without introducing separate Hilbert axioms for these properties.

This distinction will be important when reconstructing the actual
axiomatic dependencies of the Midsegment Theorem.

## 8. Structural Results Already Available

Before any Hilbert axiom is introduced, `HilbertCore` already provides
results including:

```text
sameDirectionStep_symm
ray_eq_of_sameDirectionStep

segment_swap
congruent_reverse_first
congruent_reverse_second

angle_swap
angle_congruent_reverse_first
angle_congruent_reverse_second
angle_congruent_reflexive
angle_congruent_symmetry
angle_congruent_transitivity

pointLine_swap
parallel_symmetry
parallel_swap_first
parallel_swap_second
```

These should not be classified as Hilbert axioms.

They are primarily representation laws: consequences of how segments,
rays, angles, point-defined lines, and congruence relations have been
encoded.

## 9. Dependency Structure of HilbertCore

The bottom layer of the current Hilbert route can therefore be summarized
more accurately by separating the primitive incidence language from the
betweenness-based constructions:

```text
Primitive vocabulary

Point       Line       OnLine
  |
  +-------------------+
  |                   |
Between        SegmentCongruent
  |                   |
  +--> SameDirectionStep
  |         |
  |        ray
  |         |
  |       Angle
  |
  +--> LineCollinear
            |
         PointLine
            |
         Parallel

UnorientedAngleCongruent
            |
          EqvGen
            |
      AngleCongruent
```

`Congruent` is obtained from the segment representation together with
`SegmentCongruent`.

One feature is especially important: the primitive `Line` / `OnLine`
incidence language and the betweenness-based `PointLine` construction
coexist in the core, but they are not yet identified by Hilbert axioms.

That relation becomes part of the next layer and is therefore exactly the
kind of dependency that should not be inferred from the core definitions
alone.

---

## 10. First Architectural Boundary

At the end of `HilbertCore` we do not yet have Hilbert geometry as an
axiomatic theory.

We have instead:

```text
primitive geometric vocabulary
        +
derived geometric objects
        +
representation laws
```

In particular, three relations that will later be central to the Finlay
proof,

```text
Congruent
AngleCongruent
Parallel
```

already belong to the public geometric language, but none should simply
be classified as a new Hilbert axiom.

This establishes the first boundary in the Hilbert route:

```text
HilbertCore
    |
    | definitions and representation laws
    v
HilbertAxioms
    |
    | genuine geometric assumptions begin here
    v
Hilbert theory
```

The next step is therefore to inspect `HilbertAxioms.lean` and determine
exactly which parts of the geometric structure are genuinely assumed
there.
