# Log 053 --- Replacing the Legacy 3D Axiom Layer

## Why this change was necessary

The original three-dimensional route had grown around
`Hilbert3DAxioms.lean`.  That file predated the source-faithful Hilbert
axiom layer and therefore duplicated part of the spatial language:
planes, point-plane incidence, spatial incidence, order, congruence,
and Euclidean structure.

After the introduction of the canonical source layer in
`HilbertAxioms.lean`, keeping a second independent 3D axiom system was
no longer acceptable.  The goal was therefore not to rewrite the whole
downstream library, but to replace the old foundation while preserving
the public API expected by Book XI, the Smith/Wyler dimension-free
development, and the Coxeter files.

## The new spatial entry point

The replacement module is

```text
CGJteamLab/HilbertSpaceIncidence.lean
```

Its role is deliberately split in two.

First, it contains source-derived spatial incidence results built from
the new Hilbert foundation.  In particular, it provides results such as:

```text
hilbertSpace_point_off_plane
hilbertSpace_on_line_of_collinear_with_two_on_line
hilbertSpace_plane_intersection_line
hilbertSpace_plane_through_line_and_external_point
hilbertSpace_other_point_on_line
hilbertSpace_plane_through_two_intersecting_lines
hilbertSpace_point_off_line
hilbertSpace_three_noncollinear_on_plane
```

Second, it provides a compatibility facade for the old 3D API.
This facade is not a new foundational axiom system.  Its purpose is to
keep existing downstream declarations type-correct while the library is
migrated to the canonical Hilbert source layer.

A crucial example is `HilbertSpacePrimitive`.  It must remain a real
structure rather than an abbreviation, because the E4 layer contains

```lean
class Hilbert4DPrimitive
    (Geo : Geometry.Geo)
    extends HilbertSpacePrimitive Geo where
```

and therefore relies on the generated projection

```text
toHilbertSpacePrimitive
```

This compatibility detail turned out to be essential for preserving the
Coxeter E4 development.

## Drop-in replacement

The migration was tested as a genuine import replacement rather than as
a downstream rewrite.

The old import

```lean
import CGJteamLab.Hilbert3DAxioms
```

was removed from the active dependency graph and replaced by

```lean
import CGJteamLab.HilbertSpaceIncidence
```

in the four active entry points:

```text
CGJteamLab.lean
CGJteamLab/Hilbert3DInterface.lean
CGJteamLab/HilbertDimensionFreeIncidence.lean
CGJteamLab/SalasAxioms.lean
```

The important point is that the downstream theorem bodies were not
rewritten merely to accommodate the new foundation.

## Compatibility issues found by the build

The full build exposed two useful dependency facts.

First, `HilbertDimensionFreeCone.lean` uses derived collinearity lemmas
such as

```text
PrimCollinearCycle
PrimCollinearSwap
```

which live in `HilbertPlaneTheory.lean`.  The old 3D module had exported
them transitively.  To preserve the old import surface,
`HilbertSpaceIncidence.lean` therefore imports `HilbertPlaneTheory`.

Second, the Coxeter E4 layer depends structurally on
`HilbertSpacePrimitive` through the extension mechanism described above.
Replacing that structure by an abbreviation removed the projection
`toHilbertSpacePrimitive` and produced a large cascade of E4 errors.
Restoring the compatibility structure removed the cascade.

Several intermediate failures were also caused by stale `.olean` files.
Rebuilding the changed dependency chain was necessary before testing the
next layer.

## Validation

The migration was validated incrementally through the critical modules:

```text
HilbertSpaceIncidence
HilbertDimensionFreeIncidence
HilbertDimensionFreeCone
Coxeter.E4Incidence
```

After rebuilding these dependencies, the complete command

```text
lake build
```

passed successfully.

This is the key result of the migration: Book XI, the dimension-free
Smith/Wyler route, and the Coxeter route all build with the new spatial
entry point and without an active dependency on `Hilbert3DAxioms.lean`.

## Removal of the old module

After the successful full build, all remaining references to
`Hilbert3DAxioms` were only historical comments.  These comments were
updated, and the obsolete file was removed from the active repository.

The architecture is now conceptually:

```text
HilbertCore
    |
HilbertAxioms
    |
HilbertPlaneAPI
    |
HilbertPlaneTheory
    |
HilbertSpaceIncidence
    |
    +-- Hilbert3DInterface / Book XI
    +-- HilbertDimensionFreeIncidence / Smith-Wyler
    +-- Coxeter E4 and higher-dimensional developments
```

The old parallel 3D axiom foundation is no longer part of the build.

## Current status

The important architectural boundary is now clearer:

- `HilbertAxioms.lean` is the source-faithful Hilbert axiom layer;
- `HilbertPlaneTheory.lean` contains the established derived planar
  theory;
- `HilbertSpaceIncidence.lean` is the spatial entry point and temporary
  compatibility surface;
- higher-dimensional developments no longer need a separate
  `Hilbert3DAxioms.lean` foundation.

This does not yet mean that every historical compatibility class has
been eliminated.  It means that the duplicate foundational module has
been removed without breaking the existing mathematical development.

The next documentation task is to update the architectural descriptions
of the 3D, dimension-free, Wyler, and Coxeter routes so that they reflect
this new dependency structure.
