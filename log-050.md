# Log 050 --- A Source-Faithful Hilbert Axiom Layer

## Separating Hilbert's axioms from the geometry built above them

The Hilbert development has reached a point at which two different roles
must be separated explicitly.

The first role is foundational: to record Hilbert's axiom system as closely
as possible to the source. The second role is operational: to provide the
plane-oriented interfaces already used throughout the existing Lean library.

These roles had previously been partially mixed. The existing plane API was
useful for proving geometry, but some of its declarations already contained
choices adapted to the later library rather than to Hilbert's original
formulation.

The new file

``` text
CGJteamLab/HilbertAxioms.lean
```

is intended to remove that ambiguity. It is a source layer, not a working
plane theory and not a replacement for the existing derived results.

Its guiding principle is:

> The foundational file should state Hilbert's axioms, while compatibility
> with the existing library should be handled by a separate adapter.

This produces the architecture

``` text
HilbertAxioms.lean
        |
        v
HilbertPlaneAPI.lean
        |
        v
HilbertPlaneTheory.lean
        |
        v
existing geometry library
```

The distinction is important. Source fidelity and backward compatibility
are both required, but they should not be encoded in the same layer.

## 1. The file follows Hilbert's five axiom groups

The new axiom file preserves the source organization:

``` text
Group I    incidence       I.1-I.8
Group II   order           II.1-II.4
Group III  congruence      III.1-III.5
Group IV   parallels       IV
Group V    continuity      V.1-V.2
```

No theorem of the later synthetic development is inserted merely because it
is convenient for downstream proofs.

The file also avoids adding assumptions coming from the other research
routes in the project. In particular, Smith, Wyler, Salas, Coxeter, and the
dimension-free experiments do not contribute axioms to this layer.

This makes the module a reference point against which later interfaces can
be audited.

## 2. Group I restores Hilbert's spatial incidence language

A decisive change is that planes are present explicitly.

The ambient `Geometry.Geo` structure already supplies points, lines, and
point-line incidence. Hilbert's three-dimensional incidence language also
requires a type of planes together with point-plane incidence. The new file
therefore introduces these as primitive data and states I.1-I.8 over them.

This matters immediately in several places.

Axiom I.3 is represented with its two distinct clauses:

- every line contains at least two distinct points;
- there exist three pairwise distinct noncollinear points.

The first clause is genuinely universal over lines. It is not replaced by
the weaker statement that some line contains two points.

The later incidence axioms retain their spatial meaning. A line whose two
distinct points lie in a plane lies entirely in that plane, distinct planes
with a common point have another common point, and four noncoplanar points
exist.

Thus I.7 and I.8 keep Hilbert's dimension information rather than being
collapsed into a purely planar incidence package.

## 3. Pasch is explicitly planar

The source formulation of II.4 is a plane axiom.

That fact becomes important once the same geometric language is used in
three dimensions. A line can be disjoint from a triangle for reasons that
have nothing to do with the planar separation expressed by Pasch.

The new Group II therefore states Pasch only after supplying the plane of
the triangle and requiring the cutting line to lie in that plane.

This is more than a cosmetic difference. It prevents a planar theorem from
being silently promoted to an ambient three-dimensional axiom.

The remaining order axioms retain the primitive betweenness relation already
present in `Geometry.Geo`.

## 4. Primitive angle congruence is kept primitive

The most important representation decision occurs in Group III.

The existing geometry library has a derived angle-congruence relation built
as an equivalence closure. Such a relation is extremely convenient for
later proofs because reflexivity, symmetry, and transitivity are already
available structurally.

That convenience is inappropriate in a source-faithful axiom file.

Hilbert does not begin by assuming an equivalence relation on angles. The
properties of angle congruence are developed from the congruence axioms.
The new axiom layer therefore uses the primitive unoriented-angle relation
from `Geometry.Geo` directly.

In schematic form:

``` text
primitive angle relation
        |
        v
Hilbert Group III axioms
        |
        v
derived congruence properties
```

rather than

``` text
equivalence closure
        |
        v
Hilbert Group III interface
```

This prevents derived structure from being smuggled into the foundation by
the representation itself.

The same source-oriented discipline is used for angle construction. The
target plane and the chosen side of the target line are explicit, and the
uniqueness conclusion is uniqueness of the resulting ray.

## 5. Group IV states uniqueness, not existence

Hilbert's parallel axiom is also easy to strengthen accidentally.

The new file does not postulate the existence of a parallel line. It records
only the uniqueness statement belonging to Group IV: in the relevant plane,
through a point outside a line there is at most one line that does not meet
the given line.

Parallelism is therefore kept as an in-plane notion involving two lines in a
common plane together with disjointness.

This is especially important in the spatial setting, where two disjoint
lines need not be parallel because they may be skew.

## 6. V.1 is Archimedean and V.2 is genuinely maximal

The continuity group required the largest change in representation.

Axiom V.1 is expressed by finite chains of congruent copies of a segment laid
off along a ray. This directly represents the Archimedean statement: for two
nondegenerate segments, finitely many consecutive copies of one eventually
pass beyond the endpoint of the other.

Axiom V.2 is deliberately not replaced by a modern completeness principle.
The file does not identify Hilbert completeness with Dedekind completeness,
Cauchy completeness, existence of suprema, or any other convenient analytic
substitute.

Instead, V.2 is represented as the maximality statement Hilbert actually
uses. For this purpose the file introduces an abstract structure carried by
a line:

``` text
points
betweenness
segment congruence
```

and a notion of admissible extension preserving and reflecting the old order
and congruence relations while satisfying the fundamental one-dimensional
properties.

Line completeness then says that every such extension embedding is
surjective. In other words, there is no proper admissible extension.

The auxiliary line structures used to formulate this statement are
metatheoretic bookkeeping. They are not additional geometric axioms.

## 7. Theorem-level material remains outside the axiom file

A source-faithful foundation is useful only if it remains small in the right
sense.

Results such as the ordering theorem for four points, uniqueness theorems,
symmetry and transitivity results, and the larger body of Hilbert plane
geometry belong to derived theory. They should not migrate into
`HilbertAxioms.lean` merely because an older compatibility class expects a
stronger interface.

This point became particularly important during the migration. Attempting
to reconstruct the old plane interface directly inside the new adapter began
to reproduce theorem-level arguments that already existed in the project.
That was the wrong architectural direction.

The correction was to keep the new axiom file source-faithful and make the
compatibility layer thin.

## 8. Compatibility is now a separate layer

The existing project contains a substantial Hilbert plane theory used by
Book Zero, Euclid, Coxeter, Wyler, and other developments. Rewriting that
corpus would provide no mathematical benefit and would create a second,
competing version of already established proofs.

The final migration therefore uses three distinct roles:

``` text
HilbertAxioms.lean
    source-faithful Hilbert foundation

HilbertPlaneAPI.lean
    compatibility and transport to the old plane API

HilbertPlaneTheory.lean
    existing derived plane theory
```

The old theory was not ported theorem by theorem. Its import was redirected
through the compatibility layer, and the complete project continued to
compile.

This is a significant architectural result. It shows that the project can
acquire a cleaner foundation without discarding the large proof corpus built
above the previous interface.

## 9. What the new file is for

`HilbertAxioms.lean` now has a sharply defined role.

It is not the place to collect every geometric principle useful in the
project. It is not the public working language for ordinary planar proofs.
It is not a dimension-free abstraction. It is not an attempt to make all
existing downstream code depend directly on primitive Hilbert axioms.

It is the source-faithful foundation against which those other layers can be
measured.

This gives the project two complementary views of the same geometry:

``` text
historical / foundational view
        Hilbert axiom groups

working / proof-engineering view
        plane interfaces and derived theory
```

The adapter between them makes the relationship explicit instead of hiding
it inside strengthened classes.

## 10. Consequence for the geometry library

The new organization clarifies a general principle that has appeared
repeatedly throughout the project:

> An axiom layer and a working theorem interface are different mathematical
> objects, even when they describe the same geometry.

The axiom layer should preserve the logical strength and formulation of the
source. The working interface should expose operations and results at the
scale needed by later proofs. Derived theory should connect the two rather
than being silently folded into the foundation.

For the Hilbert route this distinction is now represented directly in the
file structure.

The immediate result is a cleaner dependency chain and a more reliable basis
for future audits of three-dimensional geometry, Euclidean constructions,
and alternative synthetic routes.

## 11. Current status

At the end of this stage:

- `HilbertAxioms.lean` contains the new source-faithful Hilbert axiom layer;
- all five source groups are represented, including spatial incidence and a
  genuine maximality formulation of V.2;
- primitive angle congruence is kept separate from the library's derived
  equivalence closure;
- `HilbertPlaneAPI.lean` provides the compatibility bridge;
- `HilbertPlaneTheory.lean` retains the existing derived proofs rather than
  duplicating them;
- the complete Lean project builds successfully with the new dependency
  chain.

The foundational reconstruction is therefore no longer only a proposed
cleanup. It is integrated into the production dependency graph while the
existing theorem corpus remains intact.
